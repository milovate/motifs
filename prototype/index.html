Product story in one glance

design extraction

A menu-bar capture app builds a portable bundle (shot / clip + text + optional logs), then routes it through a destination adapter. OpenCode is the first adapter (today’s plugin path). Other tools plug in later without rewriting capture.

1 · TriggerGlobal hotkey, tray click, or agent-requested capture.
2 · CaptureInstant window shot + AX text, or short session recording.
3 · ComposeAnnotate, describe, pick skills / project, optional AI summary.
4 · SendChoose destination → adapter delivers draft / ticket / file.
01

Instant mode (ships / exists)

Frontmost window screenshot + accessibility text → floating composer → OpenCode draft session. Matches current OpenCode Appshots behavior.

02

Destination chooser (abstraction)

Same bundle, different adapters: OpenCode plugin, clipboard, local folder, later Cursor / Slack / Linear / Jam-compatible export.

03

Session mode (Jam-inspired)

Record a window/screen clip, attach console/network when available, on-device summary + repro steps, then hand the richer bundle to a destination.

Destination adapters

plugin surface

Adapter contract

interface Destination {
  id: string
  label: string
  capabilities: ("draft"|"submit"|"file")[]
  send(bundle: CaptureBundle): Promise<Result>
}

Capture Kit owns capture + compose. Plugins only implement send().

Why this shape

OpenCode stays a first-class plugin, not the product core. Adding Cursor or Slack later should not fork Instant/Session capture logic.
