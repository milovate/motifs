Capture Studio: product and design prototype

Branch feature/capture-studio in opencode-appshots-fork. Static UI prototype: nothing on this page is functional. Select any text and press H to highlight it, then open the notes pane (top right) to comment. Refer to a wireframe detail by its pin, for example S4-3.

TL;DR

  • Idea: one Mac capture app that combines the speed of Appshots (one hotkey, frontmost window, image plus text) with the depth of Jam (recording, logs, device context, AI summary).
  • Core model: every capture becomes a local Bundle. A Destination plugin receives the bundle. OpenCode is the first destination. Others plug in later through the same interface.
  • Baseline: the current helper already has the composer, region capture, annotation, @skill mentions, dictation and a safe OpenCode handoff. The plan extends it and does not restart it.
  • Rule kept from today: capture happens only on user request, and no destination sends or runs anything without a final user action.

3. Jam feature inventory

Grouped from Jam docs and the Mac page. "Mac" marks features specific to Jam for Mac.

PrivacyClient-side secret filter on headers and JSON bodies (JAM_DOES_NOT_SAVE_SECRETS); auto-blur for Recording Link sessions; binary payload placeholders.
RoutingShareable link; destination picked before "Create"; "Send to app" later; integrations: Linear, Jira, Slack, GitHub, Notion, Asana, GitLab, Zendesk, Intercom and others; webhook jam.created.
AgentsMCP server (details, console, network, user events, metadata, screenshots, transcript, chapters, frames, search, comments); CLI that also records (jam record run) and installs agent skills for Claude Code, Cursor, Codex and OpenCode.
Key point: Jam is cloud-first. The agent gets a link and pulls context through MCP or the CLI. Our product is local-first: the agent gets the bundle itself in an unsent draft.

6. Product model: Capture, Bundle, Destination

  Hotkey / menu                    local only                      plugin boundary
 +--------------+    +-------------------------------+    +---------------------------+
 | Capture      |    | Bundle                        |    | Destination               |
 |  - Appshot   |--->|  media: shots, regions, clip  |--->|  OpenCode   (first)       |
 |  - Region    |    |  context: AX text, device,    |    |  Clipboard / Markdown     |
 |  - Record    |    |           logs (later)        |    |  Folder                   |
 +--------------+    |  note, @mentions, redactions  |    |  Claude Code, Cursor, ... |
        |            +-------------------------------+    |  Linear, GitHub (later)   |
        v                       ^                         +---------------------------+
   Composer (S4) ---------------+  user reviews, edits, picks destination, then hands off
  • Capture produces media. It does not know the destination.
  • Bundle is the one source of truth: a local folder with a manifest. The composer edits it.
  • Destination declares what it accepts (images, video, text, size) and how it hands off. The composer hides or converts media that a destination cannot accept.

8. Data and plugin contracts (sketch)

A sketch for review, not final code. The destination interface is the plugin boundary that other agent apps can implement later.

type Media =
  | { kind: "window"; png: string; app: string; windowTitle: string }
  | { kind: "region"; png: string; rect: Rect }
  | { kind: "clip"; mp4: string; durationMs: number; trim?: [number, number];
      transcript?: string; keyFrames?: string[] };

interface Bundle {
  id: string;
  createdAt: string;
  note: string;                       // canonical text; @mentions derive from it
  media: Media[];
  context: {
    windowText?: string;              // accessibility tree dump
    selection?: string;
    device?: DeviceInfo;
    console?: LogEntry[];             // phase 3
    network?: NetworkEntry[];         // phase 3
  };
  include: Record<keyof Bundle["context"], boolean>;
}

interface Destination {
  id: string;                         // "opencode", "clipboard", "folder"
  label: string;
  accepts: { image: boolean; video: boolean; maxBytes?: number };
  status(): Promise<"ready" | "not-installed" | "needs-auth" | "not-running">;
  targets(): Promise<Target[]>;      // projects, sessions, teams, folders
  actionLabel(target: Target): string; // "Review in OpenCode"
  prepare(bundle: Bundle, target: Target): Promise<HandoffResult>; // must not submit
}
  • prepare places the bundle where the user reviews it. It never submits, sends or runs a model. This keeps today's consent rule for every destination.
  • The composer converts media that a destination does not accept (clip to key frames) before prepare, and shows the conversion in S6.

10. Open decisions

  1. Shell: keep the Swift helper and add UI there, or move the UI to Electron and keep Swift only for capture and accessibility? The current composer, region capture and annotation editor are Swift.
  2. Destination plugins: in-process JavaScript modules (like the OpenCode plugin today) or separate executables with a small JSON protocol?
  3. Recording limits: maximum clip length and resolution. Jam allows one hour in 4K; agents mostly need short clips.
  4. Video to agents: most agent models accept images, not video. Is "key frames plus transcript" the default for all agent destinations?
  5. Logs source: browser extension (like Jam) or Chrome DevTools Protocol for apps that run with a debug port.
  6. Product name: "Capture Studio" is a working name for this fork.
